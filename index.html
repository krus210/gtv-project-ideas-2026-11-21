Где Go-инженер продуктовой разработки может сделать инструмент, который сам использует в работе, может измеримо показать пользу и набрать звёзды. Метрики GitHub сняты 21.11.2026 через gh api. Оценки по шкале 1–5 и потолок звёзд — моя экспертная оценка, а не измерение. Веса итогового балла можно поменять ниже.

Как запускать, чтобы появился адопшн

  1. Сначала используй сам. Две-четыре недели гоняй инструмент на рабочих задачах и собери цифры «до → после»: секунды, токены, доллары, минуты CI. Это и заголовок README, и доказательство для визы.
  2. README как лендинг. Сверху GIF или asciinema (снимается в vhs), одна цифра и установка в одну строку: go install, brew, curl | sh. Если ниша занята брошенным лидером, добавь сравнение с ним.
  3. Запуск в один день. Show HN, r/golang, r/programming или r/LocalLLaMA для AI-тем, Gophers Slack, Хабр и Telegram-чаты (Podlodka AI Club, Devhands). Через 1–2 недели — PR в awesome-go, awesome-mcp-servers и соседние awesome-списки.
  4. Встраивайся в чужие экосистемы. Пиши модуль для testcontainers, GitHub Action, интеграции с LangChainGo, genkit и eino, отвечай в issues брошенного лидера («есть замена»). Это даёт и звёзды, и зависимых.
  5. Для визы звёзд мало. Собирай всё вместе: dependents («Used by»), скачивания релизов и Homebrew, импорты на pkg.go.dev, issues и PR от людей из компаний, упоминания в статьях и докладах, письма пользователей. Скрин каждого такого сигнала сохраняй сразу.
  6. Темп релизов. Еженедельный changelog и быстрые ответы на issues в первые два месяца. Звёзды от запуска быстро забываются, а живой трекер удерживает пользователей.

Источники: GitHub REST API (stars, pushed_at, open_issues, releases) на 21.11.2026; поиск GitHub по нишам — проекты, созданные в 2026 году на Go и Rust, отсортированы по звёздам. «Заброшен» означает, что последний релиз или пуш был больше года назад. Цифры в поле «Метрика для демо» — гипотезы, которые нужно измерить, а не обещания.
